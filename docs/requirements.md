### 策略与回测

管理和添加各种策略，使用历史行情开展个股及多策略研究，形成研究结论与报告。

| 功能方向 | 已明确的内容 |
| --- | --- |
| 策略管理 | 支持添加各种策略，并预留独立策略接口文件，方便后续扩展。用户授权助手决定接口的专业设计。 |
| 个股历史回测 | 使用历史行情对个股进行回测。 |
| 个股单策略回测 | 对指定股票使用一个策略进行回测。 |
| 个股多策略回测 | 对指定股票使用多个策略进行研究；独立对比或组合运行的具体方式待讨论。 |
| 多策略选股交集回测 | 支持多个策略一起筛选股票，取所选策略共同符合的股票，再对交集开展回测；不限于两个策略。 |
| 策略兼容与冲突 | 考虑策略之间本质上互相冲突的情况，组合筛选与回测时需要识别和处理冲突；具体处理机制待讨论。 |
| 收益平原回测 | 在单策略或多策略条件下，研究策略、持仓管理、止盈止损、持仓数量及仓位比例等参数变化，寻找合适的稳定参数区间；遵循晚间判断、下一交易日操作的时序。 |
| 市场环境匹配 | 策略应与大盘风格和情绪相匹配；回测需考虑风格转变后的表现下降，并提示转变风险、提供交易建议。用户提出考虑权重，具体机制待讨论。 |
| 交易信号与指导 | 当研究支持单策略或多策略交集在当前环境下有效时，生成下一交易日的交易信号，给出预期收益及退出条件，为后续操作提供指导。 |
| 止盈止损研究 | 通过回测研究止盈、止损等交易条件，用于后续操作计划；具体条件及判定方式待讨论。 |
| 持仓与减仓止盈 | 回测需支持持仓数量与比例的研究，以及减仓、部分止盈的情况；部分卖出后继续管理剩余持仓。 |
| 回测操作路径 | 找到优质回测结果后，能够查看该次回测完整路径上的操作记录，理解操作过程，为后续实际操作提供指导。 |
| 报告库 | 保存策略研究与回测成果，得出研究结论，并输出策略研究报告。 |

多策略选股交集的用户示例：A 策略选出 10 只股票，B 策略选出 9 只股票，两者共同选中 3 只，对这 3 只开展回测。该示例仅解释交集含义，实际需支持多个策略共同参与。

策略扩展接口方向及回测研究建议记录在 [策略研究设计](strategy-research-design.md)。目前仍是需求与设计讨论阶段，接口代码及回测功能在开始开发后实现。

#### 行情追踪工具的已确认方向

- 既能发现当天符合条件的股票，也要持续查看其后续走势和状态变化。
- 用户所说的“短板”按“断板”理解：连续涨停中断，隔几天再次涨停，需要能够追踪这一完整过程。
- “龙头四次涨停”是用户举例，暂不将四次设为固定条件；连续涨停次数、断板间隔及再涨停识别规则待讨论。
- 每日连板高度股票需保留按日期查看的需求，便于研究每日变化。
- 工具中的股票名称、六位代码、点击跳转与返回、批量选择，以及研究任务进度控制和曲线展示遵循全局规则。
- 数据接入时需核验本地 TDX 日线与 MCP 是否覆盖这些工具所需字段，特别是板块资金、历史板块归属及涨停状态；数据缺口后续明确。

情绪估值公式，来自用户提供的图片：

> 市值（亿元）= 当期盈利（亿元）× 复合增速系数 × 基准 PE × 大盘水位系数 × 情绪溢价

已确认：

- 财务数据希望由软件自动获取，减少手动查询和录入。
- 当期盈利采用最近 12 个月归母净利润（TTM），换算为亿元参与计算。
- 其他系数的具体定义尚未给出，需要继续讨论。
- 用户提供了表单和结果参考图，包含预期年增速、行业 PE 预设、大盘指数点位、情绪溢价系数和实际市值输入，以及理论市值、基本面底座和隐含情绪溢价结果。
- 当前先记录参考，软件架构建立后进一步分析该估值法；本轮没有开始架构或功能开发。
- 截图、输入项与预设详见 [情绪估值参考记录](emotion-valuation-reference.md)。截图中的手动盈利输入和代码前缀，最终按已确认的自动 TTM 获取及六位代码规则处理。

### 已确认的日线研究与操作流程

- 大部分回测与研究以日线为基础。
- 用户晚上完成研究或回测，使用截至当时已知的数据判断策略或多策略选股交集是否适用于当前大盘风格情绪，并形成交易信号。
- 前一交易日晚间得到信号，下一交易日执行买入或卖出。这里的“第二天”按下一交易日处理。
- 卖出、止盈与止损条件都在晚间研究中判断；得到卖出信号后，下一交易日才能执行卖出。
- 回测及收益平原采用同一信号与执行时序，避免研究结果与实际操作方式不一致。
- 减仓及部分止盈也遵循晚间判断、下一交易日执行的时序；回测继续跟踪剩余持仓及其后续退出。
- 信号需包含预期收益及退出条件；回测用于研究止盈、止损等条件，为后续操作提供指导。
- 必须关注市场风格转变风险，研究单策略或交集组合在风格转变前后的表现，并在转变时提供交易建议。
- 买卖的具体模拟成交时点与价格、信号有效性的判定标准、预期收益估计方式及风格转变后的具体动作，后续讨论。

### 已确认的回测操作路径查看需求

- 提供查看回测完整操作路径的入口，能够从研究结果找到对应回测的操作记录。
- 在获得优质回测数据后，查看该次回测从开始到结束的操作过程，帮助理解并指导后续操作。
- 操作记录需覆盖买入、持仓变化、减仓与部分止盈、最终退出等过程，并保留晚间判断与次交易日执行的对应关系。
- 具体页面位置、图表与记录的联动方式、操作依据展示内容，以及优质结果的评价标准，后续讨论。

## 已确认的数据需求

### 本地 TDX 日线数据

- 读取用户下载到本地的通达信（TDX）日线数据。
- 下载和更新由用户自行完成；软件需要读取用户已更新的本地数据。

### 通达信 MCP 服务

- 接入通达信 MCP 服务，获取股票信息。
- MCP 接入后，相关数据自动刷新。
- 本地日线数据与 MCP 数据相互补充，两个来源都需要支持。
- MCP 的具体连接方式、可获取字段及刷新频率尚未确定，接入前再明确。

### 财务数据自动获取

- 情绪估值需要软件自动获取财务数据，支持最近 12 个月归母净利润（TTM）的计算或读取。
- 将具体财务数据接入配置纳入设置，复用已有配置与缓存，减少日常重复输入。
- 实施前核验通达信 MCP 实际开放的财务字段、历史范围及权限；如有缺口，再讨论是否补充独立财务数据源。
- 当前已核对公开文档，尚未实测用户的 MCP 连接或账户权限。
- 文档证据：通达信公式系统提供归母净利润等财务字段；Tushare 利润表 API 提供净利润、报告期、实际公告日期与报表类型。这些证据说明财务数据自动获取可行，不代表已经确认通达信 MCP 的全部字段。
- 参考：[通达信财务函数文档](https://help.tdx.com.cn/gspt/docs/markdown/redword/functionlist.html)、[Tushare 利润表文档](https://tushare.pro/document/2?doc_id=33)。数据提供方尚未新增或选定。

### 启动读取与缓存

- 用户打开软件时，自动读取两个来源当前可获得的最新数据；MCP 自动读取以服务已接入为前提。
- 本地数据的新旧取决于用户自行下载更新的情况。
- 必须提供缓存，避免每次启动都进行耗时的重复读取。
- 缓存需要能够识别数据更新，兼顾启动速度与数据新鲜度。
- 具体缓存策略、可接受的启动耗时、两个来源的合并与冲突处理方式待讨论。

## 已确认的全局交互规则

### 股票代码与名称

- 所有出现股票代码的地方，都必须同时显示对应股票名称。

### 全选与按板块选择

- 所有涉及选择的地方，都需要提供全选功能及按市场选择功能。
- 用户明确：按市场选择采用板块分类，例如主板、创业板、科创板等。
- 完整板块分类、全选作用范围、非股票选择场景如何应用此规则待讨论。

### 研究与回测任务的进度及控制

- 所有研究、回测任务都必须提供进度条，让用户了解软件当前在做什么及运行进展。
- 覆盖单策略、多策略、交集回测、收益平原参数扫描，以及市场、个股和估值等研究任务。
- 统一提供暂停、恢复／继续运行、停止功能；用户本次所说的“回复”按“恢复”理解。
- 暂停后能够继续同一任务的剩余工作，不需要从头重跑；停止用于结束当前任务，与暂停区分。
- 支持退出软件或电脑重启后继续未完成的研究和回测，进度与恢复所需状态需要持久保存；从最近保存的进度继续，无需整项重跑。
- 支持同时创建、打开和管理多个回测任务，并在本机资源允许时并行计算；任务中心需要呈现运行、排队、暂停和可恢复等状态。
- 多任务各自保留配置、数据版本、进度、控制和结果；不能因切换当前页面而停止其他任务。实际同时计算的数量和资源限额需在实现时验证。
- 进度计算方式、控制操作的响应边界、保存频率及恢复交互后续设计时明确。

### 曲线与趋势展示

- 曲线是用户认为最直观的展示方式，需要作为账户复盘、研究与回测结果的重要呈现形式。
- 必须能够查看收益曲线、亏损曲线，并根据研究内容提供其他相关曲线，不局限于这两类。
- 曲线需能体现整个过程中的变化，便于观察盈利、亏损及风险如何发展。
- 具体曲线清单、指标口径、默认展示组合后续确定；“亏损曲线”与回撤、浮亏等指标的关系尚未定义。
- **2026-10-11 用户确认：所有 K 线与按日曲线支持点击日期追溯。** 回测查看所选日期、任务、策略组合及参数快照下的判断和操作；账户收益查看所选账户当天的成交、资金流水和日期事件；个股日 K 查看该股票当天分时、开收高低及量价信息。
- 收盘信号与下一交易日执行分开呈现，不能将当晚生成的信号显示为当天成交；没有操作的日期明确显示无操作。收益平原按当前参数组合追溯，多任务之间不能混用记录。
- 日期详情可切换前后日期；关闭或进入股票详情后返回，恢复原图表日期、区间、筛选和滚动位置。收益、回撤、操作路径应追溯同一份研究记录。
- 历史分时依赖数据源覆盖。真实数据未接入或缺失时展示未接入/缺失状态，不能从日线反推并冒充真实分时；当前 HTML 原型仅使用显式标注的合成示例。

## 建议，尚未确认

以下仅用于后续讨论，不作为已确认需求或直接开发依据。

- 启动时先展示缓存数据，再在后台检查并增量刷新，减少等待时间。缓存展示期间标明更新时间与刷新状态。
- 分别显示本地日线与 MCP 的更新时间；其中一个来源不可用时，保留可用数据并说明当前状态，避免将旧数据当成最新数据。
- 从股票页面返回时，保留上一页的筛选条件、已选股票和滚动位置，方便连续复盘。
- 将单策略选股与多策略交集放在相同条件下对比，检验交集是否改善表现；交集按历史选股时点计算。具体评估方案见策略研究设计。
- 分开设计信号组合权重与资金分配权重，并根据当时可获得的大盘风格与情绪进行匹配；具体模型见策略研究设计中的待讨论建议。
- 首次使用通过简短引导完成必要的数据源和账户费率配置；高级配置提供合理默认值，具体流程后续确定。
- 常用页面展示数据更新时间与连接状态；需要修复配置时提供直接入口，帮助日常使用减少进入设置的次数。
- 费率可按账户配置并供交易记录、模拟账户及回测统一引用；保存实际使用的费用配置版本，设置调整后的历史记录处理方式需明确。
- 两个模块中的资讯可复用同一来源与缓存，在不同页面按场景展示，具体结构待讨论。
- 财务数据保存报告期、实际披露日期、来源及修订版本；用于历史研究时只使用判断时点之前已经披露的版本。
- 财务缓存按新披露或修订财报更新；亏损、历史数据不足及字段缺失等情况在情绪估值页面说明，不默默填入无依据的系数。
- 研究与回测的进度同时展示当前阶段、已完成／总工作量及运行状态；工作量尚不能确定时展示阶段与活动状态，避免显示无依据的百分比。
- 长任务在后台运行，允许用户浏览其他页面；返回任务时仍能查看进度并操作暂停、恢复和停止。
- 暂停保留已完成工作及必要的运行状态；停止后的部分结果如保留，应明确标注未完成，不作为完整回测结论。
- 曲线候选包括收益金额与收益率、资产与净值、已实现及未实现盈亏、回撤、仓位与现金，以及不同策略和基准的对比；详细口径及联动建议见策略研究设计。
- 曲线支持选择日期区间、缩放、悬停查看数值，并与操作记录联动；在相关曲线上标记买入、减仓、退出及市场风格变化，便于理解波段过程。
- 行情追踪工具使用持续跟踪池，记录入选日期与原因，以及连续涨停、断板、间隔交易日数和再次涨停等事件；进入个股日线页时联动定位对应事件。
- 连板高度按每日梯队展示，并提供最高连板高度随日期变化的曲线；板块资金提供单日及累计变化等候选视图，口径明确后再选择默认展示方式。
- 用户明确 T06“异动追踪”指监管／重点监控与临近期限结束；价格、成交量或突破候选不作为监管依据，旧量价异动接口仅兼容保留。
- 监管记录分来源、类型和起始日期保留，包含明确受监控的基金；普通异常波动、常规 ST／退市风险分类不混入。严重异常波动与实际重点监控分别标识。
- 期限按来源披露或预计截止展示，临近截止按已核验年度休市日历计算；期限届满、来源移除均须待核验，不能自动宣称已解除，也不能统一套用 10 个交易日。当前名单不倒灌历史研究；实现与来源见 [监管与期限追踪](regulatory-watch.md)。

## 已确认的八项补充功能

用户已确认采纳以下八项补充功能。具体字段、参数、文件格式及实现细节继续讨论；首版范围与开发开始时间尚未确定。

| 功能要求 | 具体内容及目的 |
| --- | --- |
| 晚间复盘工作台 | 汇集数据更新状态、大盘风格、板块与跟踪池变化、当前持仓和待处理事项；按数据检查、市场研究、持仓复盘、候选研究、次日计划组织日常流程。 |
| 次日计划与实际操作对照 | 将研究信号转成可保存的交易计划，记录依据、拟操作数量或比例、退出条件及关联报告；次日关联实际成交、未执行或调整原因，之后对照计划与实际结果复盘。 |
| 统一观察与跟踪池 | 汇集策略候选、趋势龙头、异动和估值候选，保留入选原因、来源、日期、标签及状态变化；持有、观察、已退出等状态及跟踪结束规则后续确定。 |
| 交易导入与账户对账 | 支持券商导出文件的导入、预览及去重，并可手动补录；对照现金、持仓和资产快照，处理部分成交、费用、分红与资金出入，避免重复记录和金额不一致。具体券商与文件格式待确认。 |
| 数据可用性检查 | 展示各来源的数据截至日期、历史覆盖、缺失或冲突、连接状态；研究前检查所需数据，标明排除样本和缺口。核验 MCP 财务、资金及历史状态字段，历史股票池和板块归属等覆盖另行明确。 |
| 回测验证与研究可重现 | 将参数寻找区间与后续验证区间分开，展示样本量、不同环境表现及验证状态；明确次日模拟成交价、费用、滑点及无法成交的处理。保留每次运行的数据、策略、参数和规则版本，便于对比、重跑并复核结论。 |
| 账户和组合层面的仓位约束 | 在持仓数量、比例及止盈止损之外，讨论单股和行业集中度、可用资金、总仓位等约束；多信号同时出现时，按明确的候选排序与分配规则形成次日计划，并记录无法执行的原因。具体限制由用户配置或后续研究确定。 |
| 自动保存、备份与分享隐私 | 复盘和闪记自动保存，账户及研究记录在本机保存并自动备份，支持恢复与完整导出。分享卡片可选择隐藏账户标识、资产金额和持仓数量等信息。任务支持退出软件或重启电脑后从保存进度继续；断网时可使用的功能仍待确认。 |

- 参数寻找与验证方法参考：[QuantConnect 参数优化文档](https://www.quantconnect.com/docs/v2/writing-algorithms/optimization/parameters)；成交价、时间与滑点建模参考：[QuantConnect 股票成交模型文档](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/supported-models/equity-model)。这些仅是方法参考，未选定该框架；A 股成交约束按所属市场及历史日期另行核验。

## 技术方案

总体分层架构初案已获用户认可。2026-10-11 开始第一步桌面工程：Electron 入口与受控文件保存，复用现有 HTML 界面。首步 JSON 文件仅承载笔记、配置和演示工作区，不作为正式账户流水数据库；后续 SQLite 与本地业务服务按独立步骤实现。参见 [分步开发说明](development.md)。

### 总体结构建议

采用一个模块化的本地桌面应用，发布时作为一套软件安装；内部职责分为界面、本地业务服务与后台计算进程。五个功能模块共享数据、股票身份、账户记账、研究任务及报告服务。

| 部分 | 负责的工作 | 初步技术候选 |
| --- | --- | --- |
| 桌面入口 | 窗口、应用生命周期、受控的本地通信与运行环境启动。 | Electron。 |
| 界面与图表 | 五个功能模块的页面、统一股票入口与返回、曲线查看、任务进度及操作。 | React 与 TypeScript，图表库在 UI 设计阶段选择。 |
| 本地业务服务 | 数据接入、缓存与查询、账户记账和对账、交易计划、跟踪池、研究管理与备份。 | Python 常驻本地进程，由软件管理启动和退出。 |
| 后台计算 | 日线回测、策略交集、收益平原、批量估值及研究任务，向任务管理器回报结果和进度。 | Python 独立计算进程，按资源限制管理并发。 |
| 业务记录保存 | 账户流水、复盘笔记、计划、跟踪状态、配置、任务索引和研究版本清单。 | SQLite。 |
| 行情和研究数据保存 | 标准化日线、历史财务及批量结果、曲线和操作记录等数据文件。 | Parquet 等本地文件格式，具体分区与查询方式后续确定。 |

- 这是根据项目需求提出的技术组合；取舍包括维护界面和计算两套运行环境，并将所需依赖一起打包。最终选型和性能目标继续讨论，不指定未经验证的资源占用数值。
- 界面通过受控接口请求本地业务服务，由后者统一调用数据接入、账户与任务服务；页面不各自直接读取 TDX 文件、调用 MCP 或改写账本。
- 核心模块边界围绕业务职责划分，业务模块之间通过清晰接口协作；桌面入口负责窗口及进程生命周期，业务和计算不堆积在窗口入口中。

### 数据流与缓存建议

- TDX 本地文件、通达信 MCP、交易导入分别采用适配器，转换为统一字段后交给业务服务；将来补充财务等来源时复用同样的接入方式。
- 股票保留独立身份、名称、六位代码及市场元数据；市场信息独立保存，界面统一显示名称和六位代码，不靠字母前缀承担识别职责。
- 启动先查询本机缓存供界面使用，后台检查本地文件变化与 MCP 更新；处理新增和修订数据后发布新的可用版本，并显示数据截至日期与更新状态。
- 建立各字段与历史区间的覆盖说明、来源选择和冲突处理规则；缺失的资金、历史市场状态等字段先如实标明，接入能力核验后再确定补充方式。
- 日常页面使用最新可用数据，研究任务绑定确定的数据版本与历史可用时点；已有任务不随后台刷新改用新的数据。
- 用版本清单引用需要保留的数据文件，避免每次研究重复复制整套行情；保留与清理策略需确保保存的报告和可恢复任务仍有对应输入数据。

### 研究任务与跨重启恢复建议

- 统一任务管理器承载研究与回测，负责排队、资源限制、状态、进度、暂停、恢复、停止和失败记录。
- 多个任务共享全局计算和内存预算，收益平原内部的参数子任务也计入同一预算。可同时提交多个任务，超过可用资源时排队；前台页面、队列和正在计算的任务保持独立。
- 暂停后的任务保留保存点并释放计算额度；继续时重新进入调度。重启后按资源预算恢复队列，不同时拉起全部历史任务。具体调度、资源预估和公平性策略见研究设计建议。
- 每个任务保存数据、策略、参数、成交与费用规则版本；计算进程输出过程记录和分段结果，由业务服务协调登记和写入。
- 在完整交易日、完成的参数组合或批次等可保持一致状态的边界保存进度；暂停和停止请求展示处理状态，在适当边界生效。
- 恢复记录包含模拟日期、现金与持仓、策略阶段状态、参数扫描已完成项、必要随机状态、已写结果位置及任务配置。
- 正常退出前保存一致状态；异常中断时从最近完整保存点恢复，保存点之后尚未提交的工作可能需要重算，但不重跑整个任务。
- 下次启动识别可恢复任务，并校验数据、策略及恢复格式兼容性；继续原任务需要原版本，版本不兼容时明确说明，不静默换成新规则。
- 策略扩展接口需包含状态保存与恢复约定，避免仅能保存参数而无法恢复持仓或多阶段退出状态。

### 账户、交易与研究服务建议

- 真实账户、模拟账户与历史回测分别保存记录，并复用必要的记账与费用规则，避免相互修改持仓和资金。
- 以成交和资金记录为依据生成持仓、资产与曲线；导入和修改通过统一服务完成，保留原始导入信息及修正依据。
- 策略负责筛选和交易判断；统一引擎负责 T 晚间判断、T+1 模拟成交、部分退出、资金和费用更新、统计与操作路径。
- 参数扫描、多策略交集及市场环境匹配调用统一研究与回测服务；交易管理和策略条件分开配置，单股与组合层共用交易规则。
- 研究结果关联次日交易计划，再关联真实成交和执行原因，供账户复盘及策略报告对照使用。
- 曲线、报告和操作路径由同一份研究记录派生；界面按日期区间和股票查询，避免一次把整套历史及全部扫描结果装入界面。

### 保存、备份与发布建议

- SQLite 业务写入由本地服务协调，后台任务不各自长时间占用业务数据库写入；行情文件和计算结果分段写入并登记。
- 自动备份使用一致的数据库快照，并关联所需的数据和结果文件版本清单；恢复时检查数据库与文件是否匹配。
- 用户记录、研究结果与必要的行情版本分别制定保留策略，可重新生成的显示缓存与必要恢复状态区分保存。
- 程序更新与用户数据目录分开，版本升级需考虑数据库和任务恢复格式；MCP 凭据使用受保护的本地配置，不写入日志、研究报告或普通分享导出。
- 发布包包含所需运行环境，以安装后能直接使用为目标；具体打包方案、启动方式和性能需开发阶段验证。

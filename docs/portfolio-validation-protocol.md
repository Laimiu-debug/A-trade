# 组合验证协议

这是软件验证流程的实现约定，不是某个真实区间的收益报告。本轮不预设用户的正式研究区间，不把最近 39 日的默认预览当作持续性样本。

## 配置与执行

`PortfolioStudy(dataset, config, state=None)` 复用 `PortfolioEngine` 的实际资金账本；`step(days=5)` 每次最多推进一个子任务的指定交易日数，`checkpoint()` 保存当前引擎状态、已完成结果、训练选择和版本签名；`result()` 在未完成时也可安全读取。恢复时必须匹配原数据内容、配置和版本。

普通组合配置可以先保存。只有真正发起验证时，必须明确 `config.startDate`（训练开始）及 `config.study.trainEnd/testStart/testEnd`，满足训练结束早于测试开始。不会静默决定日期。训练和测试都必须存在交易日。

验证对象来自 `allocation.strategyIds`，可以包括已定义的独立策略和条件组合；每个对象作为单独策略单元运行 `allocation.mode=single`。所有子任务保留同一源快照、初始资金、成本、风险、股票池筛选和 Top N 配置，只改变分配模式、选择的策略单元和执行日期。各阶段从同一初始资金、空仓开始，不把训练持仓带入测试。

同一策略类型可建立多个 ID 独立的实例，分别保存参数与入口池。组合可引用已在前面定义的策略或组合，形成按依赖顺序配置的有向无环图；自引用、前向引用、重复子策略或 ID 均拒绝。`single` 只选择一个实例，也允许选择一个嵌套组合；此时组合的全部依赖仍参与选股，但持续性样本只有一个策略单元，不能把内部叶子数量算作独立策略证据。

执行顺序：

1. 每个策略单元独立运行训练段，保存净值、成交、每日候选和排除原因。
2. 同一组选集运行训练段等权组合，使用真实共享现金账本。
3. 仅按训练净收益最高选出固定策略；同分时依次用较低回撤、策略 ID 排序。质量检查失败的候选不参与选择。负收益候选仍可能是“相对最优”，不会被描述为有效策略。
4. 冻结选择和全部参数，分别运行测试段固定策略、测试段等权组合。
5. `study.rotationEnabled=true`（默认）且训练持续性通过时，在同一测试段运行软配权和硬切换账户；不通过时跳过轮动并保留原因。未执行轮动不产生轮动增益结论。

训练引擎只收到截至训练结束日的日线、交易日历和按日期记录的状态；指标可读取此前预热数据。测试数据不进入训练选择或持续性统计。源指纹在全部运行中相同，各阶段另保留引擎自己的实际输入摘要。结果还核对共同配置，避免把不同成本、资金或风险条件的结果直接比较。

研究服务先接受任务，再由后台读取配置指向的完整股票池；读取批次只控制工作量，不限制证券总数。全池组合与组合比较任务串行占用重型计算资源，避免两个完整行情账本同时载入；小型旧版任务保留原队列边界。首次冻结成功后，实际起止日期、配置与行情快照一并持久化；暂停、重启、继续都使用同一快照。真实股票池读取支持批次间取消：准备中暂停会丢弃未完成快照，继续时重新读取并冻结完整源，界面明确提示；已经完整冻结的行情不重新读取。

引擎和研究层将服务拥有的快照视为只读。时间切片复制证券容器与日线引用列表，共享只读 OHLCV 行；数据摘要采用流式 JSON 编码，避免复制全池的全部行情对象或一次生成完整 JSON 字符串。调用方不得在运行期间修改输入数据。检查点保留完整审计路径；前端通过独立 `dailyOffset/tradeOffset/decisionOffset` 分页读取，各子任务嵌套路径同样分页，不改动持久化结果。

## 持续性诊断

持续性分析只用各独立训练净值，不从信号分数、毛收益或独立交易收益均值推断。K 日窗口从训练起点顺序排列，收益为窗口末净值除以前一窗口末净值减一，首窗以初始资金为基准。未满 K 日的最后部分舍弃并列明天数；窗口之间不共享日收益。

每个窗口对策略单元收益做横截面排名，计算相邻窗口的 Spearman 相关。并列值用平均名次；所有收益相同的窗口没有可识别排名，其相关记为 `null`。要求至少 3 个不同收益行为的策略单元、至少 7 个完整窗口和 6 个有效相邻窗口对。阈值不会因为输入短而自动降低。

`study` 的默认设置：

| 参数 | 默认 | 含义 |
| --- | ---: | --- |
| `persistenceWindow` | 20 | 每个互不重叠窗口的交易日数 |
| `minWindows` | 7 | 至少完整窗口数，且有效相邻对不得少于该数减一或 6 |
| `minRankCorrelation` | 0.2 | 平均相邻排名相关下限 |
| `minPositivePairFraction` | 0.6 | 正相关窗口对比例下限 |
| `permutationCount` | 999 | 条件置换重复次数 |
| `seed` | 1729 | 固定随机种子 |
| `alpha` | 0.05 | 单侧条件置换 p 值上限 |

置换检验在每个窗口内独立打乱策略标签，保留该窗口的收益分布；统计量为有效相邻对的平均排名相关，p 值用 `(超过次数+1)/(重复次数+1)`。零假设要求标签可交换。相关策略、少量策略、长期固定的策略差异和市场状态都会限制这个解释；它不是轮动可盈利的证明，也没有校正用户反复改策略后的多重比较。相邻相关统计量共享一个排名向量，但原始收益窗口不重叠；不把各窗口对声称为独立样本。

## 质量与比较口径

缺少质量检查、源指纹不一致、共享配置不一致、隔离证券、陈旧估值或持仓涉及未记账公司行动，都阻止对应候选参与可靠训练选择，并阻止持续性通过。即便数值为正也不豁免。缺少完整公司行动账本而 `certified=false` 时，保留价格回报诊断，但不能把它认证为真实总回报。

比较展示净累计收益、年化、最大回撤、Sharpe、完整持仓波段胜率、换手率、费用与滑点。`winRatePct` 使用持仓全部卖完后的净已实现损益，`closedTradeCount` 统计完整结束的持仓波段；卖出成交级胜率另以 `sellFillWinRatePct` 保留，不混为完整交易胜率。具体定义随结果中的 `winRateDefinition` 保存。研究层 `costRatioPct=(fees+slippage)/initialCapital*100`；成本已体现在成交价和净值中，此比率只用于分解，不能再次扣减。暂无可定义指标时保留 `null`，不填零或无穷大。

## 轮动与系统研究入口

`rotationGate` 分别报告运行状态、训练持续性、数据认证、完整运行与比较一致性。只有真实执行完样本外轮动才计算 `estimatedRotationGain`（软配权减等权的净收益百分点）。软配权没有超过等权就报告“轮动没有创造价值”；超过等权但没有超过训练选定固定策略，关键检验仍未通过。没有执行轮动时该差值保持 `null`。

轮动通过 `allocation.mode=soft_rotation/hard_rotation` 接入同一账本，只用已知影子组合净收益形成下一开盘预算。`walkForward` 的时间切分、训练选择和逐折诊断独立记录；每折从相同初始资金开始。选择 `capitalMode=continuous` 时，另运行保留现金、持仓与待到账权益的连续账户，不把重置诊断拼成实盘回报。固定和等权对照冻结首折训练设置。重复使用同一工作区样本外区间改参会标为开发样本，不反过来修饰已公布的测试结果。

`systemPlateau` 强制四层可追踪参数：策略公式参数、组合方法及子策略权重、轮动窗口及阈值和冷却期、持仓数量及换仓门槛等参数。股票池、成本和网格随实验冻结。训练候选区域必须经过未参与选择的测试段及不同年份、环境验证；数据不完整或轮动门控失败的网格只作诊断，不认证平原。具体配置、邻域与质量规则见 [系统研究协议](portfolio-system-research.md)。

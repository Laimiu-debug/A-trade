账户与复盘的后续业务切片现已实现，最新行为与验收见 [账户与复盘](account-workspace.md)。市场行情现已接入本地 TDX、只读 MCP 和在线近期分时补充，使用方式与当前范围见 [市场数据接入](market-data.md)。以下“第一步”的演示范围与测试结果保留为历史记录，不能用来判断当前账户与市场页面的数据来源。

## 第一步：桌面启动与本地保存

本步使用 Electron 44.7.0 承载现有界面。界面仍在 `preview/`，桌面入口和文件访问集中在 `desktop/`；不在此步重写页面或引入业务数据库。

```powershell
npm ci
npm start
```

运行环境：Windows，Node.js 22.12 或以上。Electron 和依赖版本记录在 `package-lock.json`。应用只允许一个实例写入用户工作区；再次启动会显示已有窗口。

Electron 首次启动会下载运行包；若网络需要代理，可按 [Electron 安装文档](https://www.electronjs.org/docs/latest/tutorial/installation) 配置下载环境。本次已完成运行包下载，后续本机启动不需要再次下载。

桌面开发版中的行情、资产、交易与研究结果仍为合成示例。演示任务启动时暂停，手动运行仍使用前端计时器。笔记、显示设置、目标配置和演示工作区状态会写入真实本机文件。现有浏览器预览仍可通过 `npm run preview` 或直接打开 `preview/index.html` 使用。

## 本地文件

默认目录为 `%APPDATA%\A-trade\workspace\`。可在“设置 → 应用与诊断”查看并打开。源码目录和浏览器 `localStorage` 不作为桌面版的数据目录，两者不自动互相导入。

| 文件 | 用途 |
| --- | --- |
| `workspace-state.json` | 当前工作区；带格式版本、保存时间与演示工作区标识。 |
| `workspace-state.previous.json` | 上一份有效内容；第一次保存时也建立恢复副本。 |

文件写入使用临时文件、刷新到磁盘和替换操作，保存成功后才显示成功状态；窗口正常关闭前会等待最后一次保存。写入失败时会显示错误，关闭时提供保留窗口、重试或放弃尚未保存更改的选项。

主文件损坏而备份有效时，启动会保留损坏原件并从备份恢复，界面提示恢复情况；两份文件均不可读或版本比程序新时，拒绝覆盖并提示启动失败。最多接收 5 MiB 的工作区快照，不在此文件保存行情历史和大规模研究结果。

本步自动保留上一份有效快照，用于近期写入异常恢复；多日期历史备份、自选备份目录和正式业务库快照留到后续。系统强制结束进程或断电只能恢复到最近一次成功保存，不能保证尚未提交的输入仍在。

## 实现边界

- `desktop/main.cjs`：固定应用数据目录、单实例、启动和退出。
- `desktop/runtime.cjs`：本地静态资源协议、隔离窗口、受控通信和关闭前保存。
- `desktop/preload.cjs`：仅暴露初始状态、保存状态和打开固定数据目录，不把文件系统交给页面。
- `desktop/state-store.cjs`：快照校验、原子写入、有效备份与恢复。
- `preview/`：保留已完成的前端；通过存储适配连接桌面文件或浏览器保存。

桌面只加载本地页面；窗口启用上下文隔离与沙箱，禁用页面 Node 权限，限制导航与新窗口。具体依据为 [Electron 安全建议](https://www.electronjs.org/docs/latest/tutorial/security)。

## 界面交互约定

- 复盘、交易录入、导入核对、账户设置及阅读内容优先使用页面内编辑，保留主导航和返回入口，不用遮罩弹窗承载长表单。

## 本地 TDX 行情切片（2026-10-11）

“设置 → 数据源”由用户选择安装目录或 `vipdoc`，保存后显式扫描。启动只读取已有配置及目录状态，不自动搜索磁盘，也不自动下载通达信数据。个股列表按名称或带市场的代码检索，详情显示本地日线、成交量、数据截止日期、读取时间和未复权标识。

`service/tdx.py` 负责只读格式适配，`service/market_service.py` 使用独立 `market.sqlite3` 保存来源配置、证券目录和已验证的日线缓存。两者复用受控的 Python 通信进程，行情服务初始化失败不阻止账户请求。桌面主进程负责系统目录选择，页面通过限定的行情接口操作，不获得通用文件系统访问。

扫描先验证文件大小、首尾记录及日期范围，打开证券时再验证完整记录并计算内容哈希；同大小、同修改时间的历史修订也会更新缓存。损坏、截断和读取时发生变化的文件返回错误，保留此前有效缓存。源目录离线时可以查看已缓存的证券，并显示尚未更新的提示。

```powershell
npm run test:business
npm run test:market
```

Python 用例覆盖选目录、跨市场同码、二进制解析、名称、价格及量额单位、坏记录、缓存历史修订、源离线、重启、查询范围及账户服务隔离。Electron 行情验收入口 `test:market` 用于检查目录选择、页面搜索与日线显示、错误提示及重启恢复；验收在独立临时工作区执行，不向真实账户写入样本。具体运行结果以当次输出为准。

这一首个切片的本机文件只读验证读取 5745 个支持的股票及指数，覆盖 2022-01-04 至 2026-10-09，跳过 3783 个暂不支持的其他品种。该统计只描述当次数据集，不作为程序默认值或数据完整性的保证。后续 MCP 与分时范围见下节；自动复权、账户自动估值和 AI 行情上下文仍未实现。

## MCP、真实市场页与分时切片（2026-10-11）

市场总览、板块行情、板块详情和个股行情改为真实来源或明确空状态，不继续展示合成报价、涨跌家数、资金流或主线结论。总览将指数快照与本地日线收盘分别展示；板块目录和成分直接来自通达信。未接入的其他研究与回测页面仍处于演示阶段。

`npm run setup:market` 创建并安装 A-trade 自己的 `.venv`，桌面启动优先使用该解释器；设置了 `ATRADE_PYTHON` 时由用户提供包含所需依赖的环境。参考 TRADE 项目的只读桥接和数据校验方式，但运行代码、环境和本地缓存独立，不依赖旧项目路径。

MCP 通过隔离的 stdio 子进程调用运行中通达信终端，固定五个工具：连接状态、证券快照、K 线、板块目录和板块成分。支持日/周/月/一分钟 K 线的底层读取，当前界面提供日 K、分时与一分钟 K。接口不包含交易、推送、预警或 `refresh_kline` 下载操作，不向通达信安装目录写数据。

个股详情双击日 K，或在图表中选中交易日按 Enter，可在同一页面打开该日分时。分钟读取依次利用本地 `.lc1` 和 TQ 已有数据，并在联网启用时尝试东方财富近期分时补充。指定日期不存在时显示缺口与可用日期；“最近交易日”取实际返回日期。缺失 OHLC 保持为空，不由日线生成分时或近似分钟蜡烛。

行情缓存仍位于独立 `market.sqlite3`，按来源和证券保存。接口错误不覆盖有效缓存；东方财富断连、终端超时或本地源不可访问时，缓存结果保留来源时间并注明尚未更新。TQ 实测快照未提供行情日期，其 `asOf` 为 `null`，`receivedAt` 仅是采集时间；不能把成功轮询称为已验证的最新交易时刻。股票/指数与日线/分钟线的量额单位分别处理。

新增测试覆盖本地分钟格式、日期缺失、来源单位、文件读取稳定性、MCP 协议与字段校验、在线响应上限、错误隔离和未结束分钟排除。本轮 34 项 Node 测试通过；128 项 Python 测试中 126 项通过、2 项因 Windows 符号链接权限跳过。`test:desktop`、`test:account`、`test:market`、`test:market-live` 均完成两阶段 Electron 验收。最后一套经过真实 MCP 协议并以夹具替代终端，验证双击分时、分钟 K、失败缓存和重启配置。真实通达信连接与图表另行抽查，结果和来源限制见 [市场数据接入](market-data.md)。

此切片仍不触发账户自动估值、资产快照重算、AI 行情上下文或策略计算；这些功能需要单独确定时序、复权、可用性和核算口径。

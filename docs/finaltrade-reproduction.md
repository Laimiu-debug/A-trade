# 策略工作区接入与计算来源

桌面「策略与回测」直接提供选股漏斗、策略中心、策略运行、策略回测、收益平原、组合与系统研究及报告库。页面统一使用 A-trade 的蓝色主题、导航、中文日期控件与设置，没有产品版本切换入口。16 策略和四层漏斗沿用固定的 Finaltrade 计算来源；组合研究与历史任务保留各自创建时的计算口径。

## 固定来源

来源是用户提供的 `Final trade` 工作树，基准提交 `2a00ffe7c50b5f023a5db9f1c09ace1683eb1912`。该工作树有本地修改，因此实际版本以 `vendor/finaltrade/source-manifest.json` 中逐文件 SHA256 为准；不能把基准提交当作完整版本号。移植的源文件保持原样，桌面适配位于 `desktop/finaltrade-app.tsx`、`desktop/finaltrade-service.cjs` 和 `service/finaltrade_runtime.py`。

16 个已注册策略均保留原默认参数、参数 schema、候选池、信号条件和评分：

| 类别 | 策略 ID |
| --- | --- |
| 威科夫趋势 | `wyckoff_trend_v1`、`wyckoff_trend_v2` |
| 强度、评分 | `relative_strength_breakout_v1`、`score_only_rank_v1` |
| 同花顺主力量能 | `ths_main_force_flip_v1`、`ths_main_force_golden_cross_v1`、`ths_force_rhythm_v1` |
| 五龙、矩阵、B1 | `wulong_cluster_v1`、`matrix_signal_v1`、`b1_mtf_v1` |
| 趋势王 | `trend_king_v1`、`trend_king_limitup_v1`、`trend_king_rally_v1`、`trend_king_pullback_v1` |
| 涨停 | `emotion_limit_up_v1`、`limit_up_arb_v1` |

## 实际交互

- 漏斗支持加载输入池、分别运行四步、一键运行、每步设置、表格排序筛选、表头设置、拖动加票、终选池、观察池和导出。
- 策略中心支持原参数编辑、恢复默认、保存/应用/删除预设和策略对比；参数通过原共享状态供漏斗、信号、回测页使用。
- 策略运行显示信号和过滤参数；「加入交易计划」将股票写入待确认列表，随后「填写账户计划」打开当前账户的实际编辑器，人工核对后保存。成功保存才移出待确认，不写入成交流水。
- 回测支持后台任务、净值、交易与操作计划。全局任务中心汇总策略和组合任务，提供真实进度、暂停/继续/停止、查看、改名与删除；报告库汇总已完成任务及已导入报告包，支持恢复结果和完整 JSON 导出。
- 收益平原保留网格/拉丁超立方采样、参数轴、任务进度、区域、热力图、排序、参数回填、候选收藏、交易明细和报告导出。从侧栏进入时自动展开扫描设置。
- 个股可加入项目统一跟踪池或打开个股行情；分时改读项目真实分钟数据，不使用日线生成模拟分时。页面 AI 按钮打开产品统一面板，使用同一 AI 设置及当前页面资料。

## 行情与保存

沿用 A-trade「设置 → 数据源」选定的通达信安装目录或 `vipdoc`，计算使用 `tdx_only`。日线来自 `.day`，真实换手率还依赖安装目录下 `T0002/hq_cache/base.dbf` 的流通股本；缺失时沿用原算法的降级标记和筛选口径，不补造换手率。

运行不依赖外部 `Final trade` 文件夹。新增服务、任务、报告和缓存写入当前工作区的 `finaltrade` 子目录；不导入参考项目的配置、密钥、账户或任务。浏览器状态使用固定的 `atrade://reference` 来源；切换账户、行情或设置仅隐藏工作区，保留实际编辑器、参数和任务观察器。

桌面接入层拦截无真实输入行情时的演示分支，返回数据缺失错误。更换行情目录后，无未完成任务时自动更新服务并清除派生筛选结果；有运行、排队或暂停任务时继续使用原目录，可查看、暂停、继续或停止这些任务，新目录计算先被阻止。目录记录随任务服务保存，重启后仍按原目录恢复。服务仅监听本机临时端口，并要求桌面私有握手；退出桌面会关闭服务。

新建回测的初始资金、默认单边费用及已有日期草稿由项目设置提供；已有策略草稿不会被设置更改覆盖。这里的 `fee_bps` 仍是统一单边费率，最低佣金和分项税费不能被视为已进入该计算模型；账户成交费用继续按交割单记录。全局仓位上限供账户计划核对，策略每笔仓位仍以回测表单的显式参数为准。

本次统一交互和接口未更改策略公式、成交模型或平原评分。不同研究类型的报告仍绑定创建时的配置和计算口径，差分一致性验证不等同于对来源算法的未来数据、成交真实性或统计稳健性重新作出保证。

## 验证与重建

`npm run test:finaltrade-parity` 在两个独立 Python 进程中运行原项目与移植版，使用相同的 40 只股票、每只 540 根日线、DBF 股本和 TNF 名称数据。比较全部 16 策略的信号、交易、净值、回撤、计划和统计；同时比较三组四层漏斗与四点收益平原的参数、评分、区域和推荐结果。仅忽略运行 ID、生成时间和缓存命中状态；标签集合按排序比较，股票与交易顺序保持原样。部分策略在这份样本没有信号，不能据此声称覆盖了其全部触发条件。

2026-10-13 差分结果完全一致。宽松阈值样本的漏斗为 `40 → 29 → 29 → 15 → 8`；第 5～20 名排名窗口为 `40 → 8 → 8 → 3 → 3`。完整原始结果和汇总位于忽略提交的 `artifacts/finaltrade-parity.json` 所指向的临时目录。

另外从用户桌面已保存的真实漏斗结果中读取 5,167 只股票，用独立原版进程和同一行情目录重新计算；各项指标、所有层的股票成员和筛选顺序一致，数量为 `5167 → 114 → 1 → 0 → 0`。输入池中相同涨幅的行顺序存在差异：原 `tdx_loader.py` 按线程完成顺序收集行，仅用涨幅排序，没有证券代码作为第二排序键。此次差异仅发生在输入池并列项，第一步及后续池的排列完全一致；这不证明其他数据下的排名边界一定不受并列顺序影响。接入保留原规则，复现时需区分并列展示顺序与实际指标、成员差异。核对脚本是 `tests/finaltrade-real-funnel-runner.py`，汇总在 `artifacts/finaltrade-real-parity.json`。

`npm run test:finaltrade` 使用真实 Electron 和临时工作区，实际点击漏斗四步、保存策略预设、提交有成交的回测和四点平原扫描，并核对账户计划落库、报告改名和打开、全局 AI 上下文、真实任务暂停/继续/停止、目录切换、统一跟踪池、日期输入和缺失分时提示；不会写入用户工作区。`npm run test:finaltrade-api` 验证私有 API、数据缺失错误与配置隔离。`npm test` 覆盖既有工作区、服务约束及未完成任务跨重启保留原数据目录。

源码桌面测试完成 33 笔模拟成交、四点平原及上述衔接流程，Node 测试 376 项全部通过。已有日期草稿 `2026-02-13`～`2026-10-13` 保留。0.4.0 便携包已补齐内置运行依赖，并通过屏蔽宿主 Python/Node 的 exe 验收；具体范围见 [便携版说明](portable-release.md)。

前端构建：先执行 `npm ci --prefix vendor/finaltrade/frontend`，再执行 `npm run build:finaltrade`。构建脚本也可临时使用指定参考目录已安装的依赖，但桌面运行只读取本项目编译产物。构建默认保留此前的静态资源，供运行中的页面继续按需加载；关闭全部桌面窗口后，可设置 `ATRADE_CLEAN_STRATEGY_ASSETS=1` 再构建以清理未使用资源。Python 运行依赖见 `requirements-portable.lock.txt`；便携版构建复制固定源文件和编译页面，并排除 `node_modules`。

# 策略、回测与收益平原

本轮实现日期：2026-10-11。以下是当前代码的研究口径；候选策略尚不构成已证实的盈利策略。回测只操作隔离的模拟资金，不连接券商，不改变真实账户账本。

## 组合框架重构（当前入口）

桌面“回测工作区”已切换到 `portfolio_*` 引擎。以下旧版实现细节保留作存档，不代表新的全市场组合框架：旧版 50 只股票限制、隐式策略交集、单策略平原均不再作为新建研究的默认入口。

- **设置留在软件中。** 最近 39 个交易日、全部 A 股本地覆盖、初始资金 100000、单股新买目标上限 20% 为可编辑测试预设，不是推荐投资参数。支持指定日期、市场和板块、显式股票列表及可选真实指数基准。设置保存到本机工作台，下次可继续使用。
- **股票池不截断。** 遍历已配置通达信源的所有符合范围文件，按批读取只控制计算，不选前 50/120 只。基础资格与趋势、结构、量能池分开；每个策略独立选池。失败文件、过滤原因、历史事实未知数均报告。为控制内存，保留区间及 500 根预热，主散 EMA 使用完整历史前缀状态衔接，测试验证与全历史结果一致。
- **六个基础策略。** 主散金叉、主散紫转黄、主散持续主导、趋势突破、动量、趋势回调。持续主导是简化策略，不是 FINAL-TRADE 完整节奏波。每个策略每日对整个符合条件的池评分，使用当日排名百分位；交集、并集、加权组合显式配置，不再把选中多策略默认解释成 AND。
- **持仓参数分开。** 每策略 Top N、组合总持仓上限与单股新买目标上限分别配置。先汇总子策略目标，再应用组合约束；被裁剪预算留现金。每日原始 Top N、经过换仓门槛的候选、策略预算权重、实际股票权重分别保存。
- **三种调仓。** 风险退出后补仓、排名换仓、排名加风险。风险模式持仓不因单日金叉信号消失而卖出；收盘检查止损、止盈、持仓收盘峰值回撤及可选最长持有期，次日开盘尝试成交。其间单股实际比例可能因价格变化而漂移；20% 是新买预算上限。暂停和拒卖的持仓继续占用现金和持仓位。
- **比较和持续性。** 配置训练及样本外日期后，软件自动运行各策略 Top N 账户、等权账户、训练区选定的固定策略样本外账户。策略排名持续性只在训练区测试，至少三个不同有效策略和六对非重叠相邻窗口；样本外不参与选参。39 日预设只适合功能试跑，通常不够持续性证据。具体协议见 [验证协议](portfolio-validation-protocol.md)。
- **轮动、滚动与全系统平原。** 持续性通过后可比较软配权、硬切换、等权与训练选定固定策略；策略预算来自扣除成本的 Top N 影子账户，实际调仓仍走共享资金账本。滚动研究按折冻结训练选择；系统平原同时扫描策略、组合、轮动、持仓四层，最多 81 组参数，按邻域及样本外、年份、环境证据验收。详见 [系统研究协议](portfolio-system-research.md)。
- **任务生命周期。** `research.create` 的 `portfolio` / `comparison` / `walkForward` / `systemPlateau` 类型立即创建后台任务，股票池读取按批可中断；读取完成后保存独立快照再运行。未冻结完就暂停的任务，继续时重新冻结；冻结后的续跑只用原快照。全市场组合任务同时至多一个，避免多个完整数据集耗尽桌面内存；不按股票数量裁掉输入。旧报告仍可读取。

现已支持完整历史成分/状态与权益包导入、分红/送股/配股账本、连续资金滚动账户、参数连通区域和完整审计导出，见 [历史包协议](portfolio-history-format.md) 和 [系统研究协议](portfolio-system-research.md)。本地现存日线仍无法单独消除幸存者偏差，也不能认证含分红总回报；历史包认证限于声明范围内的内部完整性与税后现金模型。严格历史模式缺事实则排除，宽松模式明确标成诊断。运行完成不代表策略有效：未通过持续性就跳过轮动；没有完整样本外与数据质量证据就不认证平原，也不兜底推荐收益最高的单点。

新模块路径：`service/portfolio_config.py`、`portfolio_universe.py`、`portfolio_signals.py`、`portfolio_engine.py`、`portfolio_rotation.py`、`portfolio_study.py`、`portfolio_experiment.py`；前端 `preview/portfolio-workbench.js`，任务仍由 `research_service.py` 持久化。自动化验证使用隔离合成行情，不启动用户真实股票池的收益研究。

第一阶段验证记录：当时组合相关 Python 共 79 项通过，工作台、原研究界面与桌面桥接 Node 共 28 项通过；136 股隔离日线夹具通过真实 Electron 写入及重开验收。新增轮动与系统研究使用 `tests/test_portfolio_rotation.py`、`tests/test_portfolio_experiment.py` 及服务、界面契约测试继续验证。当前验证命令与结果见 [系统研究协议](portfolio-system-research.md)。这些验证证明功能与会计时序，不证明策略有投资价值。

持仓容量排序明确为：先比较封顶前聚合策略预算，再比较预算加权标准分，最后才按代码打破平局；该优先级写入检查点。大型快照与结果的编解码放在任务控制锁之外，并用确定性并发测试确认序列化期间暂停请求仍能受理。图像验收位于 `artifacts/portfolio-workbench.png`、`portfolio-result.png`、`portfolio-daily.png`、`portfolio-reopened.png`。

## 先研究，再实现

已阅读本机 FINAL-TRADE 的策略、成交引擎和收益平原实现。运行时不导入旧项目，也不依赖旧项目环境。本轮借鉴其独立策略注册、统一组合账户、量价条件、参数邻域、区域代表点和研究路径；根据源码核验调整以下行为：

| 参考源码与观察 | A-trade 的处理 |
| --- | --- |
| `backend/app/core/strategy_plugins.py` 的 `RelativeStrengthBreakoutPlugin` 用阶段收益、回撤与量比评分，没有直接要求突破此前区间高点。 | 突破候选明确要求收盘超过此前 N 日高点，突破区间排除信号当天。 |
| `chart_volume_swing_strategy.py` 的箱体突破、回踩和量能确认可解释，但条件与参数较多。 | 拆成趋势突破与趋势回调两个可单独检验的候选，避免起步便叠加大量评分。 |
| `hybrid_band_strategy.py` 组合多个技术评分。 | 暂不照搬多重加分；显式选择多策略时采用用户要求的选股交集，并保留各条件。 |
| `backend/app/core/backtest_engine.py` 的涨停套利特殊分支允许最终日线信号与同日收盘成交。 | 所有买入、卖出、止盈、止损、减仓均为 T 晚间判断、T+1 开盘尝试执行。 |
| `store.py` 的平原点循环一边赋 `point_score`、一边读取尚未赋值的邻居。 | 所有点先完成评分，再独立计算邻域；结果不依赖遍历顺序。 |
| `store.py` 的区域使用最近四点连接，可能跨越稀疏空洞；无区域时仍回退推荐最高单点。 | 仅连接网格轴上相邻一步的点，至少三个合格点构成区域；无平原时不推荐单点。 |
| 同一总体历史上的验证分数参与平原区域重排。 | 独立最终留出段不参与选参，冻结代表点之后才运行留出及双倍成本回测。 |

这些是对所读本机版本的观察，不代表 FINAL-TRADE 所有版本或所有策略。

## 候选策略和证据层级

1. **趋势突破与量能确认**：此前区间高点、上升均线和相对历史成交量。检验趋势延续假设，不能将量能解释成真实机构净流入。
2. **绝对趋势与相对动量**：正的历史区间收益与上升趋势过滤，在本次股票池中按历史动量排列，受共享现金和持仓数限制。
3. **上升趋势中的回调修复**：保持上升趋势，距近期峰值适度回调，收盘出现回升；可能将趋势反转误判为回调。

时间序列动量有公开原始研究支持作为研究假设，但原论文的资产、周期和交易结构与本项目不同，不能把原文结果直接当作 A 股这些参数的盈利证据。[Moskowitz、Ooi、Pedersen：Time Series Momentum](https://www.aqr.com/Insights/Research/Journal-Article/Time-Series-Momentum)。突破和回调是从 FINAL-TRADE 拆出的可解释候选，需要本地样本外验证。

参数寻找时记录尝试次数；即使留出段为正，也不代表已完成多重检验校正或统计显著性检验。重复查看留出结果后改规则，会让这一留出段变成开发数据，应换新的未使用区间。过拟合方法依据：[Bailey 等：The Probability of Backtest Overfitting](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)。本轮没有把自定义稳健分数称作 PBO 或 Deflated Sharpe Ratio。

## 信号、成交与资金

- 日线结束后生成计划；下一可见交易日以开盘价加不利滑点尝试成交。信号日预算固定，不能用执行日收盘权益决定当天开盘买量。
- 开盘处于买入涨停或卖出跌停时保守拒绝，不根据当天最终高低价推测开盘排队成交；缺失日线和无成交日不凭空补单。
- 共享现金、持仓数、每只证券仓位、整股单位、最低佣金、佣金率、卖出印花税、过户费和滑点统一记账。印花税默认根据卖出日期切换，用户明确覆盖时记录配置。
- T+1 可卖约束；部分止盈成功后才更新阶段状态；剩余持仓继续管理。期末按市值统计，不假造最终强制平仓。
- 记录信号、实际成交、拒单原因、费用、现金、持仓与权益路径，区分成交笔数和完整退出的持仓波段。零交易、不足样本及无法定义的指标保留空值。
- 本轮按日线研究，不声称复现真实集合竞价排队、盘口冲击或盘中止损成交。

规则核验入口：[上交所 2026 交易规则](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)、[科创板申报规则](https://edu.sse.com.cn/tib/)、[深交所创业板改革生效说明](https://www.szse.cn/www/aboutus/trends/news/t20210824_587951.html)、[财政部印花税减半公告](https://m.mof.gov.cn/czxw/202308/t20230827_3904226.htm)。当前证券名称不能还原历史 ST、上市初期和退市规则；引擎会注明保守假设与不支持的历史边界。

## 收益平原的具体定义

最多三个数值轴、125 个参数组合，支持策略参数和持仓退出参数。所有候选共享同一冻结行情、费用和资金起点。

1. 默认最后 20% 可见交易日作为最终留出；此前区间按时间切成三个互不重叠的验证块。各块独立从初始资金开始，之前的日线仅用于指标预热，不继承持仓。这里是固定候选的多时段稳健性验证，**不是滚动重新训练和实盘拼接收益**。
2. 对每个参数组合检验各块交易样本数、净收益与回撤。稳健分数结合块得分的下四分位和离散程度，不单独追逐最高收益。
3. 等全部点得分算完后，按严格轴相邻关系计算邻域稳定性；根据门槛形成连通区域。至少三个合格点才算平原，孤峰单独显示。
4. 在最佳合格区域选择中心代表点，并冻结参数。最终留出只检验此代表点，不对所有点按留出成绩重排。
5. 对同一留出段再运行双倍交易成本与滑点。无平原或最终检验失败时明确展示原因。

报告保存各参数点、各时间块、评分公式、轴取值、区域、代表点、搜索次数、验证状态与数据指纹。阈值和分数是透明的研究规则，不是收益概率。后续可增加真正的滚动选参、PBO/DSR、分市场环境检验与新数据验证；当前界面不会标成已经完成。

## 本地数据与任务

从用户在“设置 → 数据源”选择的通达信目录读取指定股票。提交时保存独立不可变快照和 SHA-256 内容指纹，之后行情目录变化或离线不改变本次结果。初版上限 50 只证券、150000 条日线，避免无界占用桌面资源。

日线目前未复权，缺少分红、除权因子、历史 ST/停牌/上市及退市证券完整状态；当前选择股票池也有选择与幸存者偏差。结果属于初步筛查，不应据此声称找到适用于历史全市场的优质策略。补齐数据之前，参数稳定性只能描述当前研究假设和可见输入。

账户、行情、研究各用独立通信进程。`research.sqlite3` 保存快照、任务、保存点与结果；后台最多两个工作线程处理任务，其余排队。这是有限并发和界面隔离，不是多核并行加速承诺。每五个模拟日或参数子任务的对应计算边界，原子保存状态与进度。

暂停先显示“正在保存”，保存完成后释放工作位。继续先排队；停止保留未完成结果。重启将未完成任务恢复为暂停，用户继续后从快照和保存点计算；策略或引擎源代码改变时拒绝接着旧状态运行，保留原报告。批量操作逐项返回结果。操作路径分页显示，但完整记录保存在本地。

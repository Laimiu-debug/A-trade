# A-trade Windows 便携版

0.4.9 提供单文件便携包 `A-trade-0.4.9-win32-x64.exe`：只需复制这一个 EXE，双击后自动准备并启动，无须安装、管理员权限或另装 Node.js/Python。同一构建首次启动解包到 `%LOCALAPPDATA%\A-trade\Runtime`，后续直接复用。首次准备显示进度；应用窗口先显示启动状态，再在同一窗口进入工作区。

0.4.9 修复本地指数目录与 MCP 成分股目录不一致导致的板块详情报错。日线列表按同一来源、相同代码核对当前成分目录，排除旧代码和其他分类，不按同名猜测成分。MCP 离线、目录为空或本地与 MCP 目录不同时，保留指数看图并标记“仅指数日线”，关闭未核对的成分入口。

0.4.8 为板块行情增加截至日期选择，默认使用本地板块指数日线快照。列表日涨幅、5日和20日涨幅、走势图及成分股观察使用相同截止日；所选日期没有日线时显示实际数据日期，缺少观察日或基准日的涨幅留空。实时报价保留为独立模式。板块涨幅来自通达信板块指数，成分归属仍使用当前通达信目录。

0.4.7 默认回测所选股票池全部股票，取消原来的默认 120 只截取。页面明确显示“所选股票池全部股票”，只有主动开启“手动限制数量”才设置数量上限。旧版草稿的日期与策略参数继续保留，隐含的旧数量限制自动迁移为全部；主动复用历史报告参数时保留报告中的原始上限。普通回测、矩阵和收益平原均支持全池，股票详情的信号复现也沿用这一范围。候选仍依据所选池阶段、板块等条件生成。

0.4.6 修复历史回测受看盘 K 线窗口限制的问题：回测按所选起止日期自动读取本地历史日线，并补足指标预热数据，无须手动调大 K 线根数。候选池预检、普通回测、矩阵回测及收益平原使用相同的日期读取方式；不同区间的缓存分别校验。看盘窗口设置不再限制回测跨度；本地确实缺少对应历史行情时，会说明需要补充数据。

0.4.5 新增“策略与回测 → 实验策略”：收缩突破·停滞退出、持续强势·再次突破、支撑收回·波动跟踪。页面读取已有扫描结果，也可手动点击“分析当前环境与选股”，按设置中的本地通达信日线重新分析；结果列出市场环境、各策略入选股票与触发依据，并明确展示数据截止日期、覆盖率及是否滞后。点击股票可查看行情，返回后保留本轮结果。进入页面不会自动扫描或创建账户。

发布包内含三组规则和 14 组历史研究摘要；完整冻结研究归档保留在研究仓库，未随 EXE 分发，因此包内历史复现入口标为缺少归档，当前环境分析与选股可独立使用。已有选股结果属于用户工作区，不内置进 EXE，也不代表实时行情或收益保证。

缓存目录以版本号和完整运行文件清单的构建指纹区分，新旧版本互不覆盖。解包先写入暂存目录，验证内容后才提交；缺少完成标记或关键入口文件会在下次启动时重新准备。并发启动共用解包锁，运行期间保留目录句柄，修复和清理不会覆盖仍在使用的目录。缓存不包含账户、配置或研究记录。

0.4.4 将相同内容的运行文件放入共享对象库 `.objects`，版本目录通过硬链接引用：相同运行库和重复字体只保存一份。Electron 引擎文件使用稳定的引擎版本信息，应用版本保留在外层 EXE 和界面中，避免每次更新都复制整个引擎。每次启动回收未运行的旧版本及无引用对象，清理中断会重试；重新打开旧版 EXE 时可再次准备其运行环境。NTFS 下仅对新建的运行暂存目录启用文件系统压缩，账户目录和系统设置不参与压缩。不支持硬链接或压缩的文件系统会保留普通文件副本。

发布仅保留简体中文、繁体中文和英文语言资源，删除 Python 依赖内的测试、示例、开发头文件和离线帮助；保留运行模块、必要元数据及第三方许可。普通目录大小可能重复计算硬链接，实际缓存占用应按文件 ID 去重后统计；可使用 `python scripts/measure-runtime-cache.py "缓存根目录"` 检查。

单文件包含完整 Electron、Python 3.13、账户与回测服务以及行情 MCP 的 Python 依赖，也不需要运行 `setup:market`。文件夹形式的便携运行包仍可用于开发和排障。

0.4.0 将选股漏斗、16 个策略、策略运行、策略回测、收益平原与报告库统一到产品导航和蓝色主题中。行情、账户计划、跟踪池和 AI 沿用项目设置，切换模块会保留编辑器和草稿；任务中心集中管理策略与组合研究的真实进度、暂停、继续、停止和报告。组合、轮动与日期验证位于“组合与系统研究”。AI 需要先在设置中配置文本模型。

0.4.1 修复节奏波策略错绑并增加注册完整性检查；节奏波卖点独立于买点和入选池检查，旧结果保留并提示重新回测。收益平原没有合格稳定区域时不推荐参数，热力图自动选择变化的参数轴，轴设置在图形不可用时仍可操作。数据目录和账户沿用原位置。

0.4.2 同时包含首次使用引导、按需读取股票日线的统一AI入口、情绪周期工具、完整二维收益平原、统一个股行情、漏斗股票跳转与可编辑交易表头。AI仍需用户配置模型后手动提问，不在进入页面时批量分析。

单文件包不需要旁置运行依赖；如果使用开发用文件夹运行包，必须保留整个文件夹，不能只复制其中的内层 `A-trade.exe`。

## 数据与旧版

默认继续使用当前 Windows 用户的 `%APPDATA%\A-trade\workspace`，所以同一用户从源码开发版切换到便携版后能沿用账户、设置、研究任务和结果。程序更新不会复制、覆盖或删除这些数据。开发版与便携版使用同一个实例锁，同一数据目录只运行一份程序。

软件免安装，用户数据单独保存在本机。换电脑时请在软件设置中备份相应数据并在新电脑恢复；AI 密钥受 Windows 当前用户加密保护，换账号或电脑后需重新配置。行情目录仍需在设置中选择，通达信 MCP 的原生组件由用户自己的通达信终端提供，发布包不包含行情文件、用户账户、密钥或通达信厂商二进制。

需要独立工作区时，可在启动进程前设置 `ATRADE_USER_DATA` 为完整路径；未设置时始终使用上述默认位置。测试使用独立目录，避免操作现有数据。

## 开发者重新打包

Windows x64 上执行 `npm ci`，使用 Python 3.13，再运行 `npm run build:portable`。构建从应用目录白名单复制源码，使用锁定的 Electron、带官方 SHA-256 校验的 Python 嵌入包和 `requirements-portable.lock.txt` 的固定依赖。构建输出到 `dist` 的新目录，不覆盖旧版本。

运行 `npm run build:exe` 会先准备上述完整运行包，再使用 electron-builder 固定版本提供的 NSIS 工具链和 `scripts/cached-portable.nsi` 生成单 EXE，不执行安装、不注册卸载项，也不自动发布。也可传入已经准备好的、同版本运行目录。重复打开由应用现有实例锁交接。构建记录保存在 `dist/latest-single-exe.json`，包含缓存键、源版本和 SHA-256；EXE 旁也提供 SHA-256 校验文本。此包未做代码签名，Windows可能显示未知发布者提示。

`npm run test:startup` 在独立工作区和缓存目录测量首次、再次启动时间，验证缓存复用、重复打开、关键文件缺失和解包中断恢复，以及同时启动。可设置绝对路径 `ATRADE_RUNTIME_CACHE` 改用独立缓存目录，主要供测试或本机排障使用；该选项不改变工作区位置。

`npm run test:exe` 对单文件执行下述完整验收，使用中文EXE名与临时目录、屏蔽宿主Python/Node，额外验证首次引导、实际日线检查、重复启动不损坏原实例，以及EXE旁不需要其他文件。验收不会操作日常用户工作区。

`npm run test:portable -- "完整的便携版目录"` 直接启动该目录的 exe，在隔离工作区验证内置策略服务、16 个策略、漏斗输入池、策略回测与四点平原、统一任务与报告，以及 136 只股票全池筛选、组合研究、日期验证和重启恢复。测试显式使用内置 Python，并屏蔽宿主 Python 路径；不代表验证真实行情、策略收益或不同 Windows 机器的兼容性。

包根目录的 `build-info.json` 记录版本、源代码提交、是否包含尚未提交的打包改动、运行环境版本和应用文件校验值。Electron、Chromium、Python 及 Python 依赖的许可文件随各自运行环境保留。

0.4.0 已在隔离目录中完成上述 exe 验收：策略目录 16 项，测试策略产生 5 笔模拟成交，收益平原完成 4 组参数；136 股筛选、20 日单策略、19 日其他日期验证、39 日组合研究，以及账户、保存参数和两类策略报告的重启恢复均通过。样本为测试生成的 TDX 日线文件。前端第三方库许可随包保存在 `resources/app/preview/finaltrade/THIRD-PARTY-NOTICES.txt`。

## 0.4.3 启动优化验证（2026-10-15）

本机使用独立工作区、禁用宿主 Python/Node，从启动单文件 EXE 到主界面可用计时；“首次”表示没有该构建的解包缓存，并非操作系统冷启动。每种情况各测一次，不代表其他电脑的性能。

| 版本 | 首次打开 | 再次打开 |
| --- | ---: | ---: |
| 0.4.2 | 44.971 秒 | 43.903 秒 |
| 0.4.3 | 7.166 秒 | 0.954 秒 |

新启动器直接解压到暂存目录，省去临时解压后逐文件复制的步骤；再次打开复用完成的运行环境。当前单 EXE 约 227.5 MB，大于旧包的约 148.8 MB，换取更快的直接解包；每个构建保留约 590 MB 的运行缓存。

399 项 Node 测试、桌面启动/取消/同窗口切换/关闭保存/重启恢复，以及实际单 EXE 的 16 策略、136 股筛选、回测、四点平原、39 日组合研究和账户/报告恢复验收通过。额外验证缓存不重写、重复打开、关键文件缺失和残留暂存恢复、并发首次启动；运行中的缓存替换会被拒绝，原窗口仍可用，缓存参数拒绝相对路径。

本次证据保存在 `artifacts/startup-baseline.json`、`artifacts/startup-optimized.json`、`artifacts/startup-guards.json` 和 `artifacts/portable-smoke.json`，构建文件及校验值见 `dist/latest-single-exe.json`。上述目录属于本地构建产物，不进入 Git。

## 0.4.4 缓存架构与验证（2026-10-15）

按文件内容的 SHA-256 共享不可变文件，以硬链接组成每个版本的独立目录；用户数据仍写入原工作区。准备阶段核验完整文件清单，提交后在全局缓存锁内清理未运行版本。运行目录句柄阻止活动版本被替换或回收。中断的回收目录可在下次清理时继续删除；没有引用的共享对象随之回收。此设计主要减少版本积累与重复文件，不合并正在写入的账户数据库、行情缓存或研究结果。

本机 NTFS 单次隔离测量如下。实际文件占用通过 Windows `GetCompressedFileSizeW` 获取，并按文件 ID 去重，不重复计算硬链接；不含目录和文件系统元数据。源码证据及结果分别为 `scripts/measure-runtime-cache.py`、`artifacts/runtime-cache-size.json` 和 `artifacts/startup-optimized.json`。

| 项目 | 0.4.3 | 0.4.4 |
| --- | ---: | ---: |
| 不重复的文件内容 | 589.8 MB | 495.1 MB |
| 实际文件占用 | 589.8 MB | 334.6 MB |
| 单 EXE | 227.5 MB | 208.2 MB |
| 首次准备至界面可用 | 7.166 秒 | 10.903 秒 |
| 再次打开 | 0.954 秒 | 1.094 秒 |

实际占用减少约 43%；首次准备增加完整校验、共享与压缩，约多 3.7 秒。压缩及硬链接不支持时退回正常文件，不承诺相同占用；其他机器的启动时间也可能不同。

399 项 Node 测试通过；裁剪后的发布 Python 运行 676 项业务测试，674 项通过、2 项因 Windows 符号链接权限跳过。缓存专项覆盖跨版本共享、重复字体共享、完整性失败、不支持硬链接时回退、运行中版本保护、旧版本回收及中断清理恢复。实际单 EXE 完成 16 策略目录、136 股筛选、回测与四点平原、39 日组合研究和账户/报告重启恢复验收。业务验收使用 `scripts/test-packaged-business.py`，只将仓库测试目录追加到内置解释器搜索路径，运行模块与依赖仍来自发布包；结果见 `artifacts/runtime-trim-final-tests.log`。

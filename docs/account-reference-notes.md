# 账户导入与复盘实现参考

研究来源：[Laimiu-debug/LaimiuTrade](https://github.com/Laimiu-debug/LaimiuTrade)。本次检查的固定提交为 `0953c1d42fe18e808197d6d06df41f1db5e01c94`。仅阅读源码，没有运行参考项目脚本，也没有接触其真实账户数据。本项目的解析器、评分规则和数据模型按自身架构独立实现。

## 从参考项目借鉴的流程

- `backend/app/services/ai.py` 的 `SCREENSHOT_PROMPT` 与 `parse_screenshot`：通过支持视觉的 OpenAI 兼容接口读取同花顺成交截图，输出日期、代码、名称、买卖方向、价格、数量。
- `backend/app/routers/trades.py` 的 `/import/screenshot`、`/pending`、`/pending/{id}/confirm`：识别结果先进入待确认列表，人工核对再生成账本记录；持仓行不能直接成为成交。
- `backend/app/services/ai.py` 的 `SCORE_DIMENSIONS`、`score_trades`，以及 `backend/app/routers/reviews.py`：仓位、回撤、计划执行、买点、卖点、情绪六维，既评价逐笔操作又汇总整日；区分 AI 建议与人工评分。
- `frontend/src/pages/Journal.tsx` 及周期复盘页面：固定模板、逐笔记录、当日总评、下一周期计划相结合。
- `backend/app/services/backup.py`、`backend/app/models.py`：每日、ISO 周号、年月复盘的备份结构；本项目可以预览这些复盘，并保留未映射的原始内容。

## 本次实现与改进

`service/imports.py` 只做解析和校验，不写账本。返回逐行预览：原始行号、标准字段、错误、警告；账本层负责账户归属、查重、用户确认和事务提交。

同花顺截图为主要入口：AI 识别后的 JSON 仍是待核对草稿。缺失日期不默认今天，缺失费用不猜测税率或佣金。持仓、委托、无法识别的业务及不合法价格/数量均保留明确行号与错误。费用不全以 `null` 和 `feeMissing` 标记，用户核对后明确填写；OCR 行还须明确人工核对。文件解析不会触发网络请求。

截图批次以原始图片哈希识别，模型结果先按成交关键字段排序再生成逐行标识，不依赖名称措辞；同值多笔保留不同序号。部分入账后，同组截图识别结果漏行或关键字段发生冲突时阻止整批继续导入，要求先核对已入账明细。不同裁剪或内容重叠的图片仍需人工检查。成交编号查重限定账户和交易日，避免跨日重复编号被误删。

截图来源只保存哈希，不将原图写进账本。识别服务生成 `ocr:<图片批次哈希>:<行号>` 标识，同一组截图再次识别时不因模型措辞或数字格式变化产生新身份；解析器严格校验该标识和来源哈希。不同裁剪、重叠截图仍需人工核对，不能按同价同量直接删除合法的多笔成交。

合同/委托编号默认不映射为唯一成交编号，避免一份委托下的合法分笔成交被错误去重；只有用户明确设置字段映射时才采用，并显示核对提示。

辅助文件入口支持 CSV/TSV（UTF-8、GB18030、UTF-16）、XLSX 和 JSON，支持常见中文/英文表头与字段映射。证券代码保留为六位字符串。XLSX 仅读取第一个工作表并提示，读取公式的保存缓存而不执行公式；限制压缩前后大小、条目数、行列数，拒绝实体声明及异常路径。旧版 XLS 需要用户另存为 XLSX/CSV。

手续费合计与分项不叠加。仅有合计时计入其他费用并提示；同时有分项且不一致时保留原始合计与明细，必须显式选择采用来源合计、分项或人工修正后才可导入。成交金额与数量乘价格不一致也使用相同差异处理流程，canonical 重预览不会丢弃原值或解除未解决冲突。表格明示的入出金方向决定资金流向，不能由股票数量或涨跌猜测。

交易导入拒绝明确标记为作废或撤销的记录，不将其还原为新的有效成交。完整历史（含作废状态）通过账本备份恢复处理。

复盘导入支持原生 JSON、参考项目 `daily_reviews/weekly_reviews/monthly_reviews` 备份及 Markdown。Markdown 保留完整原文；没有完整日期时需补填。参考项目旧六维 0–10 分不硬转换为本项目 24 项，而是保留旧评分和完整原始记录。导出的复盘 JSON 可回读；跨账户关联交易仍必须重新核验。

## 暂定评分规则 account-review-v1

共六维、24 个等权子项：仓位控制、风险与回撤、买入质量、卖出质量、计划与执行、情绪与过程。每项填写 0–4 整数及文字证据；可以明确标记不适用并写明原因。五种模板为每日、每周、每月、逐笔/回合、盘前预案/交易想法，细化市场、板块、持仓、逐笔、情绪、风险、次日计划和周期归因。

过程分 = 有证据的已评项目得分 ÷ 全部适用项目满分 × 100。未填、无证据项目仍占分母但不计得分；有原因的不适用项目才排除。没有有效评分时显示未评分，不显示满分。另显示覆盖率、证据覆盖率、维度分和待补项；`assessedScore` 仅表示已完成项目的均分，不能代替总分。

盈利、亏损和过程质量分开存放，不因赚钱自动高分或亏损自动低分。这是可解释、可迭代的第一版人工规则，不是经过回测验证的投资评级。AI 接口保留未来上下文扩展位置；策略、回测和市场研究完成后再统一打磨提示词及规则，不由 AI 自动改写人工记录。

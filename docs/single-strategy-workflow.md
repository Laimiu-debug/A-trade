# 单策略优先的六阶段研究流程

当前默认入口按以下顺序组织：基础可交易池 → 按策略风格配置漏斗 → 单策略固定参数回测 → 少量关键参数的平原测试 → 冻结后验证新时段 → 最后研究组合与轮动。旧组合、滚动与四层系统平原任务仍可打开，其创建入口归入高级研究。

## 1. 基础可交易池

在“市场与行情 → 股票池”查看，沿用全局设置中的数据来源，默认全部 A 股本地覆盖。上市时间、ST、停牌、流动性与历史资料等资格规则按已有口径执行。全部 A 股本地覆盖不意味着掌握已经退市或未保存的历史股票。

## 2. 按策略风格配置漏斗

单策略编辑器先选择一个策略，再应用对应的候选漏斗。预设会完整填入可查看、可修改的池条件；修改后属于自定义条件。入池依据始终是股票数据是否满足条件，策略信号另外计算。

| 风格预设 | 主要资格条件 | 研究目的 |
| --- | --- | --- |
| 基础池 | 不叠加趋势、结构与量能条件 | 给信号逻辑留下完整基础对照 |
| 趋势突破 | 60 日收益非负、站上上行 MA60、20 日回撤 0–8% | 允许零回撤的新高股票进入，由策略确认实际突破 |
| 趋势回调 | 趋势合格、20 日回撤 2–15%、站上 MA20、MA10 高于 MA20 至少 3 日 | 研究趋势中的回调结构 |
| 动量排名 | 60 日收益至少 5%、该窗口排名前 500 | 使用完整有效基础样本计算排名 |
| 量能观察 | 20 日量比至少 1.2，排除放量滞涨、长上影风险 | 约束量价资格，不预先要求主散买入信号 |

这些值是可解释的研究起点，未经收益优化，不是“最合适参数”。不同风格漏斗也需要作为研究假设比较，不能挑完收益后仍称其未参与调参。当前高级组合共享池设置，不能自动把不同冻结方案的独立漏斗全部原样装入一个组合。

## 3. 单策略固定参数回测

明确开发开始与结束日期，只选一个基础策略。先固定漏斗、策略参数、Top N、仓位、退出规则、资金与交易费用，再运行一次账户回测。结果沿用账户曲线选日、实际成交、仓位与下一交易日计划。不能由完成状态推断策略有优势。

服务类型为 `singleBacktest`。后端同时拒绝组合、多策略配权、轮动和隐式样本外研究，页面默认行为并非唯一约束。

## 4. 少量关键参数平原

在完成的单策略结果中点击“用此配置做参数平原”，继承该任务的配置和实际开发日期。选择 1–3 个策略或持仓参数，每项 2–5 个不同数值，总计最多 27 组；其余设置固定。不要同时优化漏斗、费用或组合参数。

本次平原只读取开发区间，不在每个候选背后自动查看新时段。报告列出实际候选配置、收益、回撤、已关闭持仓波段，以及相邻参数表现。每轴采用至多 3 个连续已测值构成邻域，边界向内平移；不补造没有测试的点。两个点可以比较敏感性，但不能形成至少 3 点的稳定区域。缺失数据、质量不合格、交易样本不足或回撤超限都会保留失败原因。

不自动推荐最高收益点。可先“查看该点逐日买卖”，该操作使用原开发期数据创建参数复核任务，不增加独立证据。人工选择候选后冻结；没有稳定开发区域也允许冻结，但会明确标成未形成稳定区、尚未验证。

服务类型为 `singlePlateau`，与高级 `systemPlateau` 草稿和结果分别保存。

## 5. 冻结后验证新时段

“冻结与新时段验证”保存完整方案，包括股票范围、漏斗、策略、仓位、退出、资金、费用、来源身份、数据指纹和计算版本。验证页仅允许填写任务名称和严格晚于开发截止日的新区间。验证账户重新从冻结的初始资金开始，之前的行情仅用于指标预热。

冻结方案来自后台已完成报告，不接受前端替换参数；删除原任务仍保留冻结记录。计算版本不兼容时需重新完成开发并冻结。验证失败后若要调参，应开始新研究；已经查看过的验证期不能继续当作未见数据。

服务类型为 `frozenValidation`。区间使用记录持久化，报告将收益表现和区间独立性分开：

- `fresh`：当前工作区未发现已记录重用，不代表收益或策略验证通过。
- `reproduction`：相同设置、数据与区间的复现，不增加独立证据。
- `developmentSample`：已用于开发，或曾以其他设置/数据验证过，不能当作新的独立证据。

记录无法发现软件之外已查看或使用的行情，也无法补回部署前已删除的旧研究。历史数据覆盖与实际成交约束仍需按报告判断。

## 6. 最后研究组合与轮动

新时段结果提供高级研究入口。先形成多个单独研究的策略，再另外定义组合、共享股票池和风险预算；不是点击入口就自动组合所有冻结方案。高级比较、持续性、软配权、硬切换、滚动验证与四层系统平原仍按原有协议运行，不能把单策略开发稳定区称为全系统认证。

## 验证

`tests/test_research_pipeline.py` 检查低维扫描、未来数据隔离、暂停恢复、冻结不可改、版本与区间限制、持久化及重复样本标记。`tests/research-workflow.test.cjs` 检查只提交冻结身份和新日期、版本失效阻断、结果标签与输出转义。`node scripts/smoke-research-workflow.cjs` 使用隔离合成日线，运行真实 Electron 六阶段流程及重启读取，不触碰用户真实股票池或任务记录。
